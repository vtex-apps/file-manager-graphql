Spec · Draft · STR-773
Bucket Access Control Integration
Encaminhamento correto de token de usuário e superfície GraphQL de política de bucket no file-manager-graphql — cobrindo as Fases 4 e 9 da RFC.
● Draft STR-773 Fases 4, 9 3 User Stories 4 Key Decisions ✓ revisado 2026-08-07
TL;DR
🔓
Problema: o file-manager-graphql hoje encaminha context.authToken (token da própria app) em toda chamada ao file-manager — isso impede o file-manager de distinguir anônimo/autenticado/admin, e vai rejeitar em massa o tráfego via Admin Panel/store-form quando o enforcement for ativado.
🔧
Solução: trocar a origem do header VtexIdclientAutCookie para context.userAuthToken (omitido quando ausente) em um único ponto do FileManager, e adicionar 4 novas operações GraphQL como proxy fino de /policies/* do file-manager, sem lógica de permissão própria.
⚠
Dependência bloqueante: a US-1 (token forwarding) é pré-requisito explícito do gate de ativação da US-4 do vtex.file-manager — sem ela, todo tráfego proxied seria tratado como anônimo.
📦
Fora de escopo: mudanças dentro do próprio file-manager, POST /policies/{bucket}/manifest (exclusiva do builder-hub), UI do Admin Panel (Fase 10), e ativação da US-4 em produção (decidida pelo time do file-manager).

Business Context
User Stories
3 stories: correção do encaminhamento de token (bloqueante para o file-manager) e a superfície GraphQL de leitura/escrita de política de bucket.
US-1
Encaminhar o token real do usuário em toda operação de arquivo
Como enforcement do file-manager · Bloqueante
Ver critérios de aceite ↓
VtexIdclientAutCookie passa a carregar context.userAuthToken, não context.authToken, em getFile/getFileUrl/uploadFile/deleteFile.
Sem token de usuário, o header é omitido — nunca enviado vazio.
Isenção da allow list para uploadFile permanece inalterada.
Mudança única no constructor de FileManager, compartilhada por toda operação de arquivo.
US-2
Ler políticas de bucket via GraphQL
Como administrador de conta
Ver critérios de aceite ↓
listBucketPolicies faz proxy de GET /policies, paginando o nextMarker internamente — o caller recebe uma lista única e completa.
getBucketPolicy(bucket) faz proxy de GET /policies/{bucket}.
403 sem o resource file-manager-bucket-config é exposto como está — sem checagem própria nesta app.
US-3
Escrever e remover a política admin de um bucket via GraphQL
Como administrador de conta
Ver critérios de aceite ↓
setBucketPolicy/deleteBucketPolicy fazem proxy de POST/DELETE /policies/{bucket}/admin.
Buckets protegidos retornam o 403 "bucket policy is immutable" do file-manager sem alteração.
POST /policies/{bucket}/manifest nunca é exposta via GraphQL — exclusiva do builder-hub.
Arch Decisions
Arquitetura
Duas mudanças aditivas ao ExternalClient FileManager já existente — nenhum client novo, nenhuma camada de autorização própria adicional.
Decisões de escopo
AspectoDecisão
Header ausente Omitido, nunca enviado vazio (D1)
Onde vivem os métodos /policies/* No FileManager existente, não um client novo (D2)
Erros do downstream (incl. 403) Relançados como estão — sem wrapper genérico (D3)
Autorização extra (Sphinx) Não adicionada — LicenseManager do file-manager já decide (D4)
Arch Decisions
Key Decisions
4 decisões arquiteturais documentadas — todas aceitas, sem pendência de validação externa.
1
Omitir o header em vez de enviar token vazio/undefined
Accepted
▾
Decisão: O constructor do FileManager só inclui VtexIdclientAutCookie quando context.userAuthToken é truthy; ausente, a chave do header é omitida, não enviada vazia.
Consequência: Alinha-se exatamente com a detecção de anônimo do file-manager — evita ambiguidade entre "header presente mas vazio" e "header ausente".
2
Métodos /policies/* vivem no FileManager existente
Accepted
▾
Decisão: listPolicies, getPolicy, setAdminPolicy, deleteAdminPolicy são novos métodos públicos no FileManager já existente, reaproveitando constructor e header.
Consequência: Mantém uma única fonte de verdade de comunicação com o file-manager; herdam automaticamente o comportamento corrigido de token da D1.
3
Erros do downstream (incl. 403) são relançados como estão
Accepted
▾
Decisão: /policies/* segue o padrão de getFile/deleteFile (relançar como está), não o de saveFile (InternalServerError genérico).
Consequência: Admin Panel recebe o motivo exato da rejeição (ex.: "bucket policy is immutable"), em vez de uma falha genérica.
4
Sem camada nova de Sphinx/@requiresAuth além do login
Accepted
▾
Decisão: @requiresAuth continua exigindo login, mas a decisão de account-administrator é inteiramente do LicenseManager do file-manager — sem checagem Sphinx duplicada.
Consequência: Evita duas fontes de autorização potencialmente inconsistentes.
Arch Decisions
Riscos
3 riscos mapeados. Nenhum bloqueia o deploy independente desta spec.
Nenhum impacto Alta prob.
US-1 é lançada antes da ativação da US-4 do file-manager
Mitigação: Seguro deployar de forma independente — sem efeito comportamental até a ativação.
Médio impacto Baixa prob.
Algum caller dependia implicitamente do token de app dar acesso elevado
Mitigação: Coberto pelo risco de ativação do próprio file-manager; esta spec só corrige o tipo de token enviado.
Baixo impacto Média prob.
Resolvers /policies/* ficam fora de sincronia com o schema do file-manager
Mitigação: Pin de versão vtex.file-manager: 0.x já existente; mudanças passam por revisão própria.
Technical Contract
Superfície GraphQL
4 novas operações, todas com @requiresAuth. Autorização de nível admin decidida inteiramente pelo file-manager (LicenseManager) — sem lógica própria nesta app.
QUERY
listBucketPolicies
Proxy paginado de GET /policies — retorna todo bucket configurado na conta do caller, com effectivePolicy, manifestPolicy e adminPolicy.
lista completa 403 sem file-manager-bucket-config
QUERY
getBucketPolicy(bucket)
Proxy de GET /policies/{bucket} — null para fontes não configuradas.
200 403 sem permissão
MUTATION
setBucketPolicy(bucket, readAccess, writeAccess)
Proxy de POST /policies/{bucket}/admin.
política gravada 403 bucket imutável 403 sem permissão
MUTATION
deleteBucketPolicy(bucket)
Proxy de DELETE /policies/{bucket}/admin.
confirmação 403 bucket imutável 403 sem permissão
